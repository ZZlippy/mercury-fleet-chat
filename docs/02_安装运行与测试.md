# Mercury Fleet MVP v1.1 安装、运行与测试

本文面向 Windows 初学者。建议优先使用“命令提示符（CMD）”；如果 PowerShell 因执行策略拦截 `pnpm.ps1`，可直接改用 CMD，或在 PowerShell 中输入 `pnpm.cmd`。

## 1. 需要的软件

| 软件 | 要求 | 检查命令 |
| --- | --- | --- |
| Node.js | 22–24 | `node -v` |
| pnpm | 9.15.9 | `pnpm -v` |
| PostgreSQL | 15 或更高 | `psql --version` |

Node.js 24 和 PostgreSQL 18 可以使用。

## 2. 打开正确的项目目录

解压源码包后，进入包含 `package.json`、`apps`、`packages`、`scripts` 和 `tests` 的目录。

CMD 示例：

```bat
cd /d "C:\你的路径\mercury-fleet-chat_v5"
dir
```

如果 `dir` 看不到 `package.json`，说明目录不正确，不要继续运行迁移或 seed。

## 3. 准备 pnpm

```bat
corepack enable
corepack prepare pnpm@9.15.9 --activate
pnpm -v
```

最后应显示 `9.15.9`。如果 PowerShell 报“禁止运行脚本”，请使用 CMD，或把命令写成：

```powershell
pnpm.cmd -v
```

## 4. 准备 PostgreSQL

如果你已经创建了角色 `mercury`、数据库 `mercury` 和 `mercury_test`，可以跳到第 5 节。

用 PostgreSQL 管理员登录：

```bat
psql -U postgres
```

然后在 `psql` 中执行。请把 `<数据库密码>` 换成你自己的密码：

```sql
CREATE ROLE mercury WITH LOGIN PASSWORD '<数据库密码>';
CREATE DATABASE mercury OWNER mercury;
CREATE DATABASE mercury_test OWNER mercury;
\q
```

如果提示角色或数据库已存在，不要重复创建，直接使用已有对象。

## 5. 安装项目依赖

```bat
pnpm install
```

不要把 `node_modules` 从另一台电脑复制过来；在当前电脑重新执行安装。

## 6. 创建 `.env`

CMD：

```bat
copy .env.example .env
```

PowerShell：

```powershell
Copy-Item .env.example .env
```

用 VS Code 打开 `.env`，检查至少下面两项：

```dotenv
DATABASE_URL=postgresql://mercury:<数据库密码>@localhost:5432/mercury
TEST_DATABASE_URL=postgresql://mercury:<数据库密码>@localhost:5432/mercury_test
```

如果你的数据库密码就是 `mercury`，随源码提供的示例值不需要修改。数据库密码与网页演示账号密码是两件不同的事，只是示例中可能恰好相同。

密码中如果含有 `@`、`:`、`/` 等字符，需要先进行 URL 编码。初学阶段使用只含字母和数字的本地开发密码会更简单。

## 7. 执行数据库迁移

```bat
pnpm migrate
```

第一次运行会显示已应用的迁移。旧数据库可能只新增后续迁移；全部已执行时会显示：

```text
No pending migrations.
```

当前源码包含：

```text
0001_init.sql
0002_outbox_processing_lease.sql
0003_order_details.sql
0004_one_context_link_per_message.sql
0005_fleet_mvp_v1_1.sql
```

迁移前建议备份重要数据库。不要手动删除 `schema_migrations` 记录。

## 8. 写入演示数据

```bat
pnpm seed
```

正确输出应类似：

```text
Seed complete. Password for all demo accounts: mercury
Fleet accounts: fleet1 ... fleet10
Operator accounts: operator1 ... operator3
```

演示登录信息：

| 入口 | 用户名 | 密码 |
| --- | --- | --- |
| 车队端 | `fleet1` 至 `fleet10` | `mercury` |
| 运营端 | `operator1` 至 `operator3` | `mercury` |

`pnpm seed` 可以重复运行：它会更新当前演示账号和档案，不应生成重复的 10 个车队账号。

## 9. 构建网页并启动

先构建网页：

```bat
pnpm build:web
```

再启动 API 和内置消息 Worker：

```bat
pnpm dev:api
```

看到类似下面内容表示服务已启动：

```text
{"level":"info","msg":"Mercury API listening on :4000"}
```

浏览器访问：

- 车队端：<http://localhost:4000/fleet/login>
- 运营端：<http://localhost:4000/operator/login>

停止服务时，在运行服务的终端按 `Ctrl + C`。

修改前端代码后需要重新执行 `pnpm build:web`，然后刷新页面。修改服务端代码时，`pnpm dev:api` 会尝试自动重启。

## 10. 推荐测试顺序

按从安全、快速到完整的顺序运行。

### 10.1 类型检查

```bat
pnpm typecheck
```

没有红色错误即通过。

### 10.2 代码规范检查

```bat
pnpm lint
```

### 10.3 单元测试

```bat
pnpm test:unit
```

本次交付的基准是 6 个测试文件、47 个测试通过。

### 10.4 前端组件测试

```bat
pnpm test:component
```

该测试不连接 PostgreSQL，用于检查任务草稿隔离、发送重试、只读角色和任务分类。

### 10.5 前端生产构建

```bat
pnpm build:web
```

出现 `built in ...` 且没有 error 即通过。

### 10.6 集成测试：会清空 `mercury_test`

```bat
pnpm test:integration
```

集成测试读取 `.env` 中的 `TEST_DATABASE_URL`，并会清空该地址对应的数据库。运行前必须确认地址以 `/mercury_test` 结尾，绝对不要指向保存日常数据的 `mercury` 数据库。

### 10.7 HTTP 端到端测试：特别危险，必须显式使用测试库

`pnpm test:e2e` 会清空 `DATABASE_URL` 指向的数据库，然后重新迁移和 seed。运行时必须临时把 `DATABASE_URL` 指向 `mercury_test`。

CMD：

```bat
set DATABASE_URL=postgresql://mercury:<数据库密码>@localhost:5432/mercury_test
pnpm test:e2e
```

PowerShell：

```powershell
$env:DATABASE_URL="postgresql://mercury:<数据库密码>@localhost:5432/mercury_test"
pnpm.cmd test:e2e
```

完成后关闭该终端，再重新打开终端运行日常开发服务，避免临时环境变量继续覆盖 `.env`。

### 10.8 浏览器测试（可选）

先安装 Chromium：

```bat
pnpm exec playwright install chromium
```

在第一个终端连接测试数据库并启动服务，在第二个终端运行：

```bat
pnpm test:browser
```

浏览器测试会创建订单和报价，建议只在测试数据库中运行。

## 11. 常见问题

### `pnpm` 不是内部或外部命令

重新运行 `corepack enable` 和 `corepack prepare pnpm@9.15.9 --activate`，然后关闭并重新打开 CMD。

### PowerShell 提示无法加载 `pnpm.ps1`

最简单的办法是改用 CMD。也可以在 PowerShell 中输入 `pnpm.cmd` 代替 `pnpm`。

### `psql` 不是内部或外部命令

从开始菜单打开 “SQL Shell (psql)”，或把 PostgreSQL 的 `bin` 目录加入 PATH。常见位置类似：

```text
C:\Program Files\PostgreSQL\18\bin
```

### `DATABASE_URL is not set`

确认项目根目录存在 `.env`，文件名不是 `.env.txt`，并且终端当前目录包含 `package.json`。

### `password authentication failed`

`.env` 中的数据库用户名或密码与 PostgreSQL 角色不一致。这里不是网页账号密码错误。

### 端口 4000 已被占用

关闭之前启动的 Mercury 终端，或在 `.env` 中把 `PORT=4000` 改成其他端口，例如 `PORT=4001`。

### 页面打开但样式或内容是旧的

停止服务，重新运行：

```bat
pnpm build:web
pnpm dev:api
```

然后在浏览器按 `Ctrl + F5` 强制刷新。

### seed 后仍显示旧邮箱账号

依次确认：

1. 终端位于这份 v1.1 项目的根目录；
2. `scripts/seed.ts` 中包含 `fleet1` 和 `operator1` 的生成逻辑；
3. `.env` 连接的是你正在查看的数据库；
4. 重新执行 `pnpm migrate` 和 `pnpm seed`；
5. 使用无痕窗口或先退出旧会话。
