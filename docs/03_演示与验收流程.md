# Mercury Fleet MVP v1.1 演示与验收流程

本文用于第一次体验系统、向他人演示或手工验收。开始前应完成迁移、seed、网页构建和服务启动。

## 1. 演示准备

打开两个浏览器标签页：

- Operator：<http://localhost:4000/operator/login>
- Fleet：<http://localhost:4000/fleet/login>

建议登录：

- Operator：`operator1` / `mercury`
- Fleet：`fleet1` / `mercury`

Fleet 和 Operator 使用独立 Cookie，因此同一个浏览器可以同时保持两种身份。

## 2. 先理解 seed 中的车队能力

`fleet1` 至 `fleet10` 均有已审核的新加坡（SG）演示档案并默认正在接单。演示数据为了制造不同匹配结果，危险品和冷藏箱能力按账号编号有所不同：

- 偶数编号车队支持危险品；
- 能被 3 整除的编号车队支持冷藏箱；
- 同时要求危险品和冷藏箱时，只有同时满足两项的车队会成为默认候选。

Operator 仍然需要在发送前确认最终收件名单。

## 3. 场景 A：提港订单完整流程

### 3.1 Operator 创建订单

在运营端选择“新建订单”，填写：

| 字段 | 演示值 |
| --- | --- |
| 订单类型 | 提港订单 `IMPORT_DRAYAGE` |
| 服务国家 | SG |
| 目的码头 | PSA Pasir Panjang Terminal |
| 送货地点 | Jurong Industrial Estate |
| 空箱归还地点 | Tuas Empty Container Depot |
| 箱型 | 40HQ |
| 箱量 | 2 |
| 计划开始时间 | 选择未来时间 |
| 危险品／冷藏箱 | 均不勾选 |

保存后，系统只创建订单并显示候选车队，不应自动静默群发 RFQ。

### 3.2 Operator 选择车队并发送 RFQ

检查“匹配／不匹配”原因，勾选 `fleet1` 所属车队并发送。

验收点：

- Operator 能看清最终发送对象；
- 暂停接单或系统账号已暂停的车队不能发送；
- 发送后订单进入询价阶段。

### 3.3 Fleet 用编号选择报价

切换到车队端，打开对应任务。消息应类似：

```text
1. 我要报价
2. 无法承运
3. 稍后回复

请回复 1 / 2 / 3 选择。
```

在输入框回复：

```text
1
```

然后输入报价，例如：

```text
220全包
```

系统应显示报价确认信息及编号选择：

```text
1. 确认提交
2. 修改报价
3. 取消报价
```

回复 `1`。如果未明确写币种，确认信息应提示当前按 USD 处理。

验收点：

- 车队业务选择没有按钮；
- 回复编号会作用于当前任务；
- 报价金额 `220` 不会被误解为第 220 个选项；
- Operator 能看到金额、币种、全包、可用性、有效期和条款字段。

### 3.4 Operator 选择报价

回到运营端，打开订单的报价页，检查该报价并点击选择。系统创建 Booking，并向车队发送接单问题。

### 3.5 Fleet 接受任务

车队端收到类似：

```text
1. 接受任务
2. 无法承运
3. 联系运营
```

回复 `1`。

验收点：

- 不要求填写司机、车牌或车辆安排；
- Shipment 初始状态为“等待码头放箱／提箱”；
- 页面明确这是一张 2 箱整票任务。

### 3.6 Fleet 更新提港运输节点

依次在聊天中输入下面含义的文本，并在系统确认问题出现后回复 `1`：

1. `全部重箱已提取`
2. `前往送货地点`
3. `送到了`
4. `等待归还空箱`
5. `全部空箱已还`

验收点：

- 每次状态更新都需要编号确认；
- 状态必须按顺序前进；
- “送到了”以后不能直接完成，仍必须归还空箱；
- 每个状态代表全部 2 个集装箱，不支持只完成一箱。

### 3.7 Fleet 上传文件

在文件类型中分别选择并上传：

1. 送货签收证明（POD）；
2. 空箱归还证明。

支持图片或 PDF，单个文件不超过 10 MB。

两类文件齐全且运输节点完成后，任务进入“等待运营审核”。

### 3.8 Operator 审核并结案

在运营端的待处理事项中打开文件：

- 如果内容不正确，填写原因并退回；
- 如果正确，审核通过。

审核通过后应同时看到：

- Shipment：已完成；
- Booking：已完成；
- Order：已完成。

## 4. 场景 B：送港订单关键流程

创建 `EXPORT_DRAYAGE` 订单，至少填写：

- 服务国家；
- 装货地点；
- 起运码头；
- 空箱提取地点；
- 计划提取空箱时间；
- 箱型和箱量。

车队接单后必须依次完成：

1. 全部空箱已提取；
2. 已到达装货地点；
3. 全部集装箱已装货；
4. 前往码头；
5. 全部重箱已还至码头；
6. 上传空箱提取证明；
7. 上传重箱交还码头证明；
8. 等待 Operator 审核完成。

验收底线：不能跳过“全部空箱已提取”，也不能在装货完成后直接把订单设为完成。

## 5. 场景 C：订单变更与报价重新确认

1. 先让车队提交一份报价；
2. Operator 修改订单中的车队可见字段，例如时间、箱型或箱量，并填写修改原因；
3. Fleet 应收到清晰的变更消息；
4. 原报价显示为已失效，但历史仍保留；
5. 车队选择“价格不变”或重新报价；
6. Operator 只能选择基于最新 Order version 和 RFQ revision 的有效报价。

还应尝试回复一个超出范围的编号，例如 `9`。系统应提示编号范围，不得改变报价或任务状态。

## 6. 场景 D：车队档案

### Fleet 操作

1. 打开“车队档案”；
2. 修改车队名称、国家、危险品能力、冷藏箱能力、联系人、联系电话或备注；
3. 提交审核；
4. 确认页面显示“待审核”；
5. 切换“暂停接单”，确认立即生效。

### Operator 操作

1. 打开车队档案审核页；
2. 对比上一份已批准档案和新提交内容；
3. 选择批准或退回并填写备注；
4. 必要时把车队系统账号设为暂停。

验收点：档案等待审核时，匹配仍使用上一份已批准版本；接单开关无需审核即可立即影响候选结果。

## 7. 演示完成检查表

- [ ] 两个独立登录入口都可使用；
- [ ] 用户名为 `fleetN` / `operatorN`，密码为 `mercury`；
- [ ] 车队业务选择只显示编号文本；
- [ ] 多任务之间的数字回复不会串单；
- [ ] Operator 创建订单后先选择收件人，再发送 RFQ；
- [ ] 报价比较包含价格以外的必要字段；
- [ ] 订单变更会失效旧报价并保留历史；
- [ ] Booking 不要求司机和车辆信息；
- [ ] 提港流程包含还空箱；
- [ ] 送港流程包含提空箱和交还重箱；
- [ ] 两类任务都需要两类文件和 Operator 审核；
- [ ] 审核通过后三个核心对象一致完成。
